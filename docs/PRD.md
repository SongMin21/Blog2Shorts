# 블로그 콘텐츠 기반 숏폼 영상 제작 웹서비스 — PRD (1p)

## 1. 한 줄 목표

블로그 URL 또는 본문을 넣으면 30~60초 9:16 숏폼 영상 초안이 자동으로 만들어지고,
장면을 확인·수정해 바로 다운로드까지 끝내는 웹서비스 MVP를 만든다.

## 2. 핵심 사용자와 핵심 흐름

- **핵심 사용자**: 강의·상품 소개 블로그 글을 숏폼으로 재가공해야 하는 콘텐츠·마케팅 담당자.
- **핵심 흐름(한 문장)**: 블로그 입력 → 대본 생성 → 장면 구성·편집 → TTS·자막 생성 → 9:16 합성 → 미리보기·다운로드.

## 3. 필수 범위 / 도전 과제 / 범위 제외

- **필수**: 블로그 URL·본문 입력 / Hook·본문·CTA 구조의 30~60초 대본 생성 / 4~6개 장면 분할 /
  블로그 첨부 이미지 우선 활용한 장면별 이미지 구성 / 장면별 문구·이미지 수정 / TTS·자막 생성 / 9:16 합성 / 미리보기·다운로드.
- **도전 과제**: 블로그 이미지가 부족하거나 저해상도일 때 장면을 채우는 방식, 합성 대기시간 단축, 대본 생성 프롬프트의 토큰 효율.
- **범위 제외(추가 구현 항목)**: 장면별 AI 이미지 생성·재생성 / 음성 종류 선택 / 배경음악 적용 / 작업 내역 저장.
  필수 흐름이 끝까지 연결된 뒤에만 착수한다.

## 4. 화면 목록과 상태

| 화면 | 로딩 | 빈 데이터 | 오류 |
|---|---|---|---|
| ① 입력 | 버튼 비활성 + 분석 중 표시 | 입력 전 안내 문구와 입력 예시 | 본문 추출 실패 사유 표시 후 본문 직접 붙여넣기 유도 |
| ② 생성 진행 | 단계 표시(분석 → 대본 → 장면) | 해당 없음 | 실패한 단계 표시 + 해당 단계부터 재시도 |
| ③ 장면 편집 | 장면 카드 스켈레톤 | 이미지 없는 장면은 플레이스홀더 + 교체 안내 | 저장 실패 알림 + 재시도, 직전 편집값 유지 |
| ④ 결과 | 합성 진행률 표시 | 완성 영상 없음 상태 | 합성 실패 사유 + 재시도 / 장면 편집으로 복귀 |

## 5. 데이터 모양(JSON 필드)

```json
{ "jobId": "string", "status": "parsing|script|scene|render|done|failed",
  "source": { "type": "url|text", "url": "string", "text": "string", "images": ["string"] },
  "script": { "hook": "string", "body": "string", "cta": "string", "targetSec": 0 },
  "scenes": [ { "order": 0, "caption": "string", "narration": "string", "imageUrl": "string", "imageOrigin": "blog|placeholder", "durationSec": 0 } ],
  "video": { "url": "string", "ratio": "9:16", "durationSec": 0, "captionOn": true } }
```

## 6. 기술 선택과 이유 (배포: Vercel)

- **프론트엔드 React** — 장면 편집 화면이 문구·이미지 단위로 상태가 자주 바뀌어 컴포넌트 단위 관리가 유리. Vercel 배포.
- **백엔드 Spring Boot (Java 17, 3.1.x)** — 기업 지정 스택. 본문 추출 → 대본 생성 → 합성을 작업(job) 단위 비동기로 처리.
- **생성형 AI / TTS: OpenAI API** — 대본 분석·생성과 음성 생성을 한 제공자로 묶어 연동 지점을 줄임.
- **영상 합성: 서버 사이드 렌더링** — 이미지·음성·자막을 9:16 mp4로 합성해 다운로드 링크로 제공.
- Vercel은 프론트엔드 기준이므로 백엔드·합성 서버의 배포 위치는 8번 질문으로 확인 필요.

## 7. 오늘 만들 "첫 화면" 1개

**① 입력 화면.** URL/본문 전환 입력창 + "영상 만들기" 버튼 + 로딩·오류 상태까지.
완료 기준: 입력값을 백엔드로 보내 `jobId`를 돌려받고 생성 진행 화면으로 넘어가는 것까지 연결.

## 8. 기업에 확인할 질문

1. 배포 환경: Vercel은 프론트엔드 기준인가? Spring Boot 백엔드와 영상 합성 서버는 어디에 배포하는 것으로 가정하나?
2. 대상 블로그 범위: 네이버 블로그만 지원하면 되는가, 다른 플랫폼도 포함인가?
3. 블로그에 이미지가 0장이거나 해상도가 낮을 때, 추가 구현 항목(AI 이미지 생성) 없이 허용되는 대체 방식은 무엇인가?
4. 영상 1건의 목표 생성 시간과 9:16 기준 권장 해상도는 어떻게 잡는가?
5. 블로그 원본 이미지 재사용에 대한 권한·출처 표기 요건이 있는가?
